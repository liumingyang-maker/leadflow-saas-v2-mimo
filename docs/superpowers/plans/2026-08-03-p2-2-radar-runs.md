# P2-2 Radar Manual Runs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add tenant-isolated, manually requested Radar Runs that preserve bounded static-page snapshots without any recurring scheduler or automatic external action.

**Architecture:** A `radar_scan` Job is the execution record and contains only the Radar Run identifier. `RadarRun` stores the immutable run configuration and terminal state; `RadarSnapshot` stores sanitized, content-addressed structural facts. Page planning derives a homepage plus bounded, same-domain observed/configured URLs; static fetch failure is recorded per page so successful pages survive.

**Tech Stack:** Flask, SQLAlchemy/Alembic, RQ Jobs, `StaticFetcher`, pytest, Ruff.
